# Чернігівський Вісник — проєкт сайту

Статичний темний новинний сайт + Cloudflare Worker-проксі до Alerts.in.ua.

## Важливі обмеження

- API-токен зберігати тільки як Worker Secret `ALERTS_IN_UA_TOKEN`, не в `public/index.html`, GitHub Pages або повідомленнях.
- Alerts.in.ua документація вказує м'який ліміт близько 8–10 запитів/хвилину з однієї IP та жорсткий 12/хвилину. Тому фронтенд перевіряє проксі кожні 15 секунд, але Worker кешує відповідь джерела на 60 секунд. Частіше звернення браузера не означає частіший запит до API.
- Перший прототип використовує `/v1/alerts/active.json`, який повертає активні записи, а не повний довідник усіх громад. Для надійного показу всіх громад потрібно додати регіональний довідник з офіційної документації та перевірити структуру відповіді реальним токеном.
- Локальна історія в браузері — не офіційний архів. Для спільної історії між користувачами потрібна база даних і окрема логіка.
- Не відображає траєкторії, координати чи прогнози руху повітряних цілей. Для цього є посилання на офіційні джерела.
- Вбудовування офіційної карти не вмикається автоматично, оскільки треба перевірити, чи дозволяє її сайт вбудовування. На сторінці є кнопка переходу до карти.

## Локальний перегляд

Відкрий `public/index.html` у браузері, але API не запрацює без Worker-проксі, що налаштований і опублікований.

## Публікація через Cloudflare Workers (статичні Assets)

1. Встанови Node.js та Wrangler: `npm install -g wrangler`
2. Увійди: `wrangler login`
3. В корені проєкту виконай: `wrangler secret put ALERTS_IN_UA_TOKEN`
4. Встав свій персональний токен Alerts.in.ua у термінал. Не вставляй його у чат або код.
5. Перевір конфігурацію `wrangler.toml`: `main = "worker/index.js"`, `directory = "public"`.
6. Конфігурація вже лежить у корені проєкту; виконай `wrangler deploy`.
7. Після публікації перевір `https://ТВІЙ-ДОМЕН/api/health`, потім `/api/active`. Успішний `/api/active` має повернути JSON з `data` та `fetchedAt`.
8. Перевір сторінку і API на мобільному телефоні. Не називай сайт офіційним сервісом.

## Примітка про структуру файлів

Для найпростішого деплою рекомендовано, щоб `wrangler.toml`, папка `worker/` і папка `public/` лежали в одному корені. У цьому архіві конфігурація зберігається в корені, `main` і `assets.directory` задані відносно кореня: якщо Wrangler не прийме `../public`, зміни на `./public` перед `wrangler deploy`.

## Домен і Google

- У Cloudflare Dashboard → Workers & Pages можна прив'язати домен, якщо він у тебе є; для `pages.dev` отдельная покупка домена не нужна.
- Google Search Console: добавь сайт как URL-prefix property для точного `https://...` адреса и пройди проверку способом, который предложит Google. После публикации запроси индексацию главной страницы.
- Индексация и место в поиске не гарантируются и могут занять время.
